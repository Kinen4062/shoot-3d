# MINI TPS

一个用 Ursina 写的迷你第三人称射击游戏。目标是**做完整、能玩、能打包**，
不是做多。

## 环境

- Python **3.12+**（Ursina 8.x 的 `Requires-Python` 是 `>=3.12`，3.10/3.11 装不上）
- Ursina **8.3.x** + Panda3D 1.10.x

```powershell
# 项目里的 .venv 已经建好，重新安装依赖：
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

## 运行

```powershell
python main.py
```

**渲染合并（M7 第一步）**
玩家 36 个零件、敌人 18~20 个零件全部烘焙成**单个**带顶点色的 mesh，
场地 36 个盒子（墙/压条/柱/盖板）合并成 1 个。同一场景的**可见** draw call
从 649 降到 75（`tools/_probe_cost.py` 量得出来），画面逐像素没有变化 ——
四张探针截图和合并前完全一致。

代价是外观不能再靠"改某个零件的 color"做效果：
受击闪白改成着色器 `flash` uniform（0~1），
面罩/灯条这类"自己会亮"的零件改成顶点色 alpha=1（着色器跳过光照）。
碰撞一点没少：墙和柱子仍有**不可见**的碰撞代理，射线和相机遮挡照旧。

**窗口图标别传字符串**：`Ursina(icon="C:/.../icon.ico")` 即使文件存在，
Windows 窗口层也会打 `Could not find icon filename` 并退回默认图标。
生产代码走 `main.window_icon()`，内部用 `Filename.fromOsSpecific()` 包一层。

**30 波通关 + 第 31 层 BOSS**

- 主线 **30 波**，清完就通关（不是无限刷）。重甲兵每 6 波一只
  （第 6/12/18 波各一只，第 24/30 波两只）；
- 通关时弹出的是**通关面板**，不是死亡面板：上面多一个 `ENTER BOSS LAYER`
  按钮，可点可不点 —— 不想打 BOSS 的玩家到这儿就能收工；
- 第 31 层只有一波：**2 只重甲 + 5 个远程兵 + BOSS「Liang」**。
  打完弹 `LIANG DEFEATED / TRUE ENDING`；
- 进 BOSS 层是**这一局的延续**：不重开、不清场、分数保留。实现上靠
  `State.CLEARED` 这个独立状态 —— 借 `GAME_OVER` 会被"死亡才重开"的判断
  走成重开一局，借 `PAUSED` 会和暂停面板叠在一起；
- BOSS 的血条挂在屏幕顶部（`combat_hud`），只在它活着时出现；
  数值上它是基础 1200 血 × 第 31 波的 4.0 倍率 = **4800**，
  正好是同波重甲兵（200×4=800）的 6 倍。

**霰弹枪（第 10 波解锁，数字键 `3`）**

7 颗弹丸 / 7 发弹匣 / 装填 1.2 秒 / 每颗 20 伤。距离分段以**玩家**为原点
（1 格 = `GROUND_GRID_CELL` = 2 米）：

| 距离 | 散布 | 单颗伤害 | 一枪全中 |
|------|------|----------|----------|
| ≤ 4 米（2 格） | 2.5° | 20 | 140 —— 第 10 波的小兵 120 血，一枪一个 |
| 4~8 米 | 2.5° → 10° 线性涨 | 10 | 70 |
| ≥ 8 米（4 格） | 10° | 10 | 70，但弹着圆半径 1.4 米，实际只中一两颗 |

两个容易踩的坑，都写在代码注释里：

- 距离不能用 `hit.distance`。射线从**相机**出发，而第三人称相机在玩家身后
  6 米，4 米的目标会量成 10 米、直接掉进减半那一档。要用玩家到敌人**中心**
  的水平距离（用命中点的话，tank 那么宽的身体又会少算半个身位）。
- 瞄准时散布只收到 `0.6` 倍，**不归零**。归零等于 7 颗全中同一点 ——
  一把精度无限、单发 140 的狙击枪，比步枪还强。单发武器仍然严格为 0。

**后台换弹**：没拿在手上的枪自动补弹，但只有 0.5 倍速；换弹途中切走、
再切回来会**接着装**，不是从头装（`WeaponState` 的状态一直在，切枪只改下标）。
慢一半是为了保留"现在换回来会卡一下"的取舍。

## 工程化

### 静态检查

```powershell
pip install -r requirements-dev.txt
python -m ruff check .     # 风格 + 疑似 bug
python -m mypy             # 类型
```

两个工具都配在 `pyproject.toml` 里，**当前是零告警**。

- `ruff` 选了 `F/E/W/I/UP/B/C4/SIM/RUF/BLE`。`BLE`（盲 `except`）是有意开的：
  这个项目要吞 Panda3D 和音频的各种异常，但每一处都得写明理由，
  所以代码里会看到 `except Exception:  # noqa: BLE001 - 理由`。
  **`tools/` 整目录不参与检查** —— 探针必须在 `from ursina import *` 之后
  import 项目模块，`E402` 是结构性的，加一堆 `noqa` 只是噪音。
- `mypy` 是**宽松模式**：ursina / panda3d 都没有类型标注，strict 会逼出一堆
  `type: ignore`，维护成本远高于收益。现在只求抓住"传错参数 / 拼错属性"。
  覆盖面是 `src/` + `main.py`（`tests/` 全是鸭子类型 stub，放进去只会淹没真错误）。

上线了才发现的问题里，有一条是这么抓出来的：`ClearPanel.reset()`
被**定义了两次**，后一个把前一个整个覆盖，于是"打完 BOSS 之后卡片缩着不还原"
这个当时以为修好的 bug 其实一直是坏的。`F811`（重复定义）报的就是它。

### 分级日志

原来是 27 处裸 `print` 散在 12 个文件里 —— 发布版想静音只有"全部注释掉"一条路，
但那会把"存档写失败""音效装载失败"一起埋掉。现在是四档，一个环境变量切换：

| `MINITPS_LOG` | 你会看到 |
|---------------|----------|
| `DEBUG` | 每条生成点重采样、每次换弹（只在排查时开） |
| `INFO` | **开发期默认**。波次、重开、装载结果 |
| `WARNING` | **打包后默认**。能跑但不对劲 |
| `ERROR` | 只留"功能已经坏了" |
| `OFF` | 全静音 |

写错的值不会炸，退回默认档。用法：

```powershell
$env:MINITPS_LOG="DEBUG"; python main.py     # 一次性的详细日志
python main.py                               # 默认 INFO
```

同时写一份到 `%APPDATA%\MiniTPS\log.txt`（超过 1 MB 轮转一份，保留 1 份备份），
行首带时间/级别/模块名。**文件打不开时只降级不抛异常** —— 只读目录、权限受限的
机器照样能玩，这才是这条日志存在的意义。CI 和探针传 `path=""` 完全不落盘。

### CI 与许可

`.github/workflows/ci.yml` 三个 job，push / PR 都跑：

| job | 平台 | 跑什么 |
|-----|------|--------|
| `test` | `windows-latest` | `pytest` |
| `lint` | `ubuntu-latest` | `ruff check` |
| `types` | `ubuntu-latest` | `mypy`（**故意不装 ursina**，靠 `ignore_missing_imports`） |

测试放 Windows 是因为这个项目只在 Windows 上验收（Panda3D 的窗口层差异足以让
测试绿而游戏坏）。`types` 不装 ursina 是为了让"类型检查该有多快"不被 panda3d
那 200 MB 拖住 —— 反正它对 mypy 来说本来就没有标注。

没有 `ruff format --check`：接 formatter 会把整个仓库重排一遍（几百行纯换行 diff），
而现有代码的手工排版（注释对齐、分组空行）是刻意留的。行长也不硬卡（`E501` 关闭）。

## 操作

开局停在主菜单，**鼠标点 START**（或按 `TAB` 循环状态机，调试用）。

对局中：`WASD` 移动、`Shift` 疾跑、`Space` 闪避、鼠标转视角、
左键开火、右键瞄准、`R` 换弹、`1/2/3` 切枪（3 是霰弹枪，第 10 波才解锁）、`ESC` 暂停。
暂停面板里 `VOLUME` 按钮循环 5 档音量，`MAIN MENU` 回主菜单。

M0 验收：窗口里只有左上角的调试覆盖层。
按 `TAB` 在 `MENU → PLAYING → PAUSED → CLEARED → GAME_OVER → MENU` 之间循环
（`CLEARED` 是为了不手打 30 波也能验通关面板）；
按 `ESC` 在 `PLAYING / PAUSED` 之间切换（再按一次必须能恢复）。

M1 验收：能自由跑动且不抖；跑到边缘被墙挡住（`pos` 停在 ±27.05，因为墙有 1 米厚度）；
贴着墙或柱子转镜头，`camera` 那行的 `dist` 会从 6.00 掉到 **0.10 左右**、
`body` 变成 `off`（角色模型自动隐藏，避免从模型内部看出去），画面始终看不到墙内部。
`dist` 在正常贴墙时不应掉到 0.00 —— 那是侧向射线把偏移量重复扣了一次，已修。
相机是**过肩视角**（`CAM_SHOULDER = 0.55`）：角色偏在画面左下，准星正前方是空的；
挂点在眼高 1.70 米（不是头顶以上的 2.60 米），俯视感没那么强。

M2 验收：四个靶子在出生点前方（`targets: 4 alive`）。
`gun` 行显示弹匣、`HIP/AIM/RELOAD` 和**当前真实散布角**（瞄准时应为 `0.00deg`）；
按住右键立刻变 `AIM`、镜头拉近、肩偏移从 0.55 收到 0.28，准星压住靶子必中；
腰射散布：手枪 0.25°、步枪 0.5°（15 米内偏差小于靶子半宽的三分之一）；
`shots` 行的 `last=` / `dmg=` 是命中诊断：`last` 是这一发打到的对象名，
`dmg=Y` 才表示真的结算了伤害。**准星压住靶子却打不中时，先看这两个值**：
`last=target_dummy dmg=Y` 说明判定没问题，问题在观感；
`last=wall_n` / `last=ground` 说明射线向上或向下偏；
`last=target_dummy dmg=N` 说明打到了但没认成敌人。
`input` 行显示最近一次按键与 `L/R` 状态 —— 右键没反应时先看这行；
靶子中弹闪白、4 发步枪击杀、3.5 秒后原地复活；
连续按住左键时 `fps` 不应低于 M1 太多（拖尾走池，不创建新 Entity）。

M5 验收：主菜单（`START` / `QUIT` + 两行操作说明 + 背景镜头缓慢环绕 6°/秒）→
打完一波（左下血条三色分档 + 3 个护盾格、右下弹药和换弹条、顶部 `WAVE n · n LEFT`、
右上 `SCORE / BEST`）→ `ESC` 暂停（`RESUME` / `VOLUME` 五档 / `MAIN MENU`）→
死亡（慢镜头 + `YOU DIED` 四行数据，破纪录多一行 `NEW RECORD`）→
`RESTART`（控制台 `[M5] run reset (restarts=1, listeners=27)`，**波次回到 1 而不是 2**）→
`MAIN MENU`。全程控制台不应出现 Traceback 或 `缺音效 / 装载失败`。

M6 验收：主菜单就有 BGM（音量偏小是故意的，压枪声）；玩家是深色装甲 + 青色面罩 + 护肩，
脚下有一圈接触阴影；地面网格跑起来一格一格地过；击杀点飘 `+120` 上浮淡出（连杀变青色）；
**Alt+Tab 切出去再切回来应该已经暂停**（且不自动恢复）；右上角 FPS ≥55 绿 / 40~54 黄 / <40 红。

### 弹道方向为什么不用 `camera.forward`

`Entity.forward` 取的是节点局部 +Z，而"屏幕正中心是哪个方向"由投影用的 lens 定义。
两者是否同向取决于引擎内部的相机朝向约定，一旦不一致，弹道会整体偏离准星，
而且不报任何错。所以 `src/core/screen_ray.py` 直接对 lens 做反投影：
取屏幕中心在近/远裁剪面上的两个点，把它们的差向量从相机局部空间变换到世界空间。
屏幕中心就是准星圆心，因此这条射线与准星严格共线，fov、相机距离、肩偏移都影响不到它。

第一次开火时控制台会打印一行 `[aim] lens中心 与 camera.forward 夹角=...deg`，
这是可复核的现场证据：0 表示两者一致，非 0 表示必须走 lens。

## 目录约定

```
main.py              唯一入口
src/core/            时钟、状态机、事件总线、输入、配置、光照、几何合并（mesh_builder）
src/entities/        玩家、敌人、子弹、道具、场地（player_body / enemy_body 是外观）
src/systems/         武器、AI、感知、生成器、计分、音效
src/ui/              HUD、菜单、调试覆盖层
assets/              模型、字体、贴图、音频
data/                数值配置 json
tests/               单元测试
```

## 四条不能破的规矩

1. **只有 `GameLoop` 一个 Entity 实现 `update()`**。其余系统都是普通对象，
   由主循环按显式顺序调用。
2. **只有 `GameClock` 能读 `time.dt`**。暂停用 `clock.paused`，
   绝对不要用 `application.paused`（它会把全局输入回调一起关掉）。
3. **不要在业务代码里写按键字符串**，一律引用 `src/core/input_map.py` 的常量。
4. **不要在 `src/` 里写 `print`**，用 `src/core/log.py` 的 `get_logger(模块名)`。
   `tests/test_log.py` 里有一条 AST 检查守着这条 —— 唯一的例外是 `log.py`
   自己那处兜底（日志文件打不开时，日志系统还没装好，绕回去会递归）。
